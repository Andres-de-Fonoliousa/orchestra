01 Architecture & Vision

Modern AI development suffers from a structural bottleneck: ephemeral amnesia. Whenever a chat session resets or quota depletes, your project context evaporates.

Orchestra solves this by introducing a Git-backed state layer. It bridges ephemeral chat sessions into a unified, version-controlled brain located at ~/.config/opencode/memory/.

02 The Daily Workflow

Orchestra operates around three core handshake commands designed to keep your cognitive state perfectly synchronized.

Phase Command Description
Initialization /handoff Loads project state, recent journal, and knowledge base into a new chat.
Capture /remember <fact> Permanently logs an architectural decision or gotcha into the knowledge base.
Finalization /done Journals the session, updates handoff state, and commits to git.

Deep Dive: /handoff

Execute this immediately upon opening a fresh chat session. The agent reads your project's .orchestra/handoff.md, aggregates recent journal entries, and renders an executive briefing:

Project: <name> · Last session: <summary> · Current state: <status> · Next steps: <actions>
Context loaded. What are we working on?

Deep Dive: /done

Triggered before closing a session or when encountering quota exhaustion. This command performs an atomic state save:

  1. Appends a structured summary to memory/journal/YYYY-MM-DD.md.
  2. Refreshes .orchestra/handoff.md with concise progress tracking (<40 lines).
  3. Triggers an automated Git commit via orchestra commit.

03 The CLI Reference

Orchestra adds ~/.config/opencode to your user PATH during installation, enabling global command execution from any terminal instance.

orchestra <command> [arguments]
Subcommand Operational Description
doctorValidates system configuration, memory integrity, and git repository status.
migrateRebuilds the SQLite full-text search (FTS5) index from markdown records.
query "<text>"Executes natural language queries across your entire project history.
syncPulls, commits, and pushes your encrypted memory repository to a private remote.
serveSpins up the local visual dashboard interface at http://127.0.0.1:8714.
run "<goal>"Initiates a headless multi-agent swarm run with automated testing gates.

04 Visual Dashboard 

orchestra serve

Launches a zero-dependency local web interface providing real-time visibility into your health checks, persistent identity, knowledge base, chronological journals, and active swarm run boards.

05 Tokens & Configuration

Global configuration is maintained in a single file at ~/.config/opencode/opencode.json:

{
  "model": "provider/model-id",
  "provider": {
    "my-provider": { "options": { "apiKey": "{env:MY_PROVIDER_KEY}" } }
  }
}
Always use environment variable interpolation ({env:VAR}) to prevent accidental secret leaks into your git history.

06 Per-Project State

Each repository maintains a lightweight .orchestra/handoff.md file (excluded via .gitignore). It serves as the active scratchpad between sessions, automatically reconciled when running /handoff or /done.

07 Migration & Upgrades

Upgrades are fully additive and automated. Running python orchestra.py upgrade backs up your existing state, applies new binaries, rebuilds indexes, and executes verification diagnostics without touching user journals or identities.

08 Plugins & Extensions

Orchestra features built-in TypeScript plugins for automated session idle journaling, alongside Windows TTS audio feedback plugins (voice-report.js) that read execution outcomes aloud offline.

09 Multi-Machine Sync

Because your memory layer is backed by an isolated Git repository, executing orchestra sync seamlessly pushes your updated knowledge base and journals to a secure private remote.

10 Troubleshooting

SymptomResolution Strategy
Chat amnesia persistsEnsure you restarted opencode after editing config; run orchestra doctor.
Empty briefing on handoffConfirm /done was executed in previous sessions to populate journal entries.
Corrupted memory stateLeverage Git history inside ~/.config/opencode/memory to revert commits.

12 Swarm Orchestration (v3)

Orchestra introduces headless multi-agent swarms. A single command spawns specialized coding sessions governed by an automated testing gatekeeper.

orchestra run "<goal>" --depth 1
        |
   [orchestrator] plans task cards
        |
   [frontend] [backend] [ui] [theme] [seo] [db] [api]
        |
   [tester] verifies -> PASS (git commit) or FAIL (rework loop)
